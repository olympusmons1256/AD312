solution.py contains two functions: selection_sort(arr), which sorts integers
in ascending order, and selection_sort_descending(arr), which sorts in descending
order. Both operate in-place by dividing the list into a growing sorted region
[0, i) and a shrinking unsorted region [i, n). Each pass finds the minimum (or
maximum) of the unsorted region and swaps it into position i. The only change
between the two functions is the comparison operator (< vs >).

COMPLEXITY ANALYSIS
Time: O(n²). The nested loops produce (n-1)+(n-2)+…+1 = n(n-1)/2 comparisons in
all cases — the algorithm never exits early, even on a sorted input.
Space: O(1). Sorting happens in-place with only a fixed number of auxiliary
variables; no additional data structure proportional to n is allocated.

ENHANCEMENTS AND STABILITY
Enhancement: descending sort required only swapping the < operator for >,
tracking the maximum element per pass instead of the minimum.
Stability: Selection Sort is NOT stable. A long-distance swap can skip over
equal elements — e.g., [3a, 3b, 1] becomes [1, 3b, 3a], reversing the original
order of the two 3s. Stability could be achieved by shifting elements instead of
swapping, but at the cost of more writes per pass (still O(n²) overall).
